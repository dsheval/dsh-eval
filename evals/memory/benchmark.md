# DSH 记忆插件测评基准

> 状态：可执行草案  
> 范围：记忆插件互比（一次只装一个）  
> 原则：记忆 ≠ 上下文；会话内能答不算记住  
> 相关：窗口组成 / 压缩 / 截断记在上下文组，本组不记那些分

本文用人话写清两件事：什么叫测过了，以及你坐到机器前该按什么顺序做。

---

## 1. 这套基准在测什么

就测一件事：

**换上某个记忆插件之后，把这轮对话关掉，再开一轮（最好连 DSH 一起退出再开），它还能不能把该记住的事答对，同时别把不该说的说出来。**

会话还开着就能答，那是窗口里还留着原文，不是记忆。

DSH 里的记忆插件做法很杂：有的写 `MEMORY.md`，有的给模型 `remember` / `recall` 工具，有的自己从聊天里抽取，有的先门控再往窗口里塞。因此不能把所有插件只塞进“随口说一句”的协议。基准分两条正式赛道：

- `passive`：不附加记忆提示，测自动抽取、自动召回的零提示体验。
- `guided`：用厂商无关的自然语言明确要求模型使用已安装的持久记忆能力，测工具驱动或需意图触发的完整能力。

两条赛道共用题面、屏障、评分和过程账，但**分开跑基线、分开排名**。都不要求某个具体工具名。统一入口仍是：

1. 用大白话把事实说进去  
2. 设一道「关会话 / 重启」屏障  
3. 用大白话再问  
4. 看它怎么回答

不要拿网上 Mem0、LoCoMo 的分数来和这里的结果横比。题不一样，接口也不一样。

---

## 2. 几条死规矩（标准）

测的时候不要改口。违反任何一条，这轮结果作废或只能当现象，不能当质量结论。

1. **必须跨会话。** 先聊一轮把事实说进去，关掉。再开一轮问。有余力就把 DSH 整个退出再开。新窗口里不能还能看到上一轮的原话。
2. **一次只装一个记忆插件。** 今天测 A 就只装 A。测完卸掉，清掉它的库和文件，再装 B。两个一起装，分不清是谁在记。
3. **必须有「什么都不装」的对照。** 不装记忆插件，再跑同一套题。如果跨会话还全对，说明题出烂了，测的不是记忆。
4. **装不上、开不起来，不打质量分。** 只能写「装失败 / 开不起来」，不能写「记忆差」。
5. **看它怎么回答，不看它调没调某个工具。** 新会话里答对了就算。没调用 `recall` 不扣分。
6. **记忆和上下文分开记。** 窗口挤不挤、压不压、截不截，记到上下文组。本组只记：隔了一轮还记不记得。
7. **结论必须带证据。** 插件版本、DSH 版本、profile、模型、题号、成功或失败、限制。证据不够就标「暂不推荐」，不要给排名。
8. **协议必须匹配且不得混排。** 自动抽取插件可进 `passive`；工具驱动、显式意图或审批型插件进 `guided`。跨协议只能并列报告现象，不能比较正确率、延迟增量或名次。

## 3. 第一周测谁（先覆盖机制，不要铺几十个）

榜上带「记忆」两个字的很多。第一周按机制各挑一个，机制覆盖到了，结论才站得住。

| 条件 | 装什么 | 它大概怎么干活 | 你重点看什么 |
| --- | --- | --- | --- |
| C0 对照 | 什么都不装 | 只有当前窗口 | 跨会话题应大面积失败；否则题废了 |
| C1 文件核 | `dsh-hermes-memory` 或 HME | 写 `USER.md` / `MEMORY.md`，启动时往窗口里灌 | 重启后文件还在不在；会不会把整文件灌进去 |
| C2 工具库 | `dsh-memory-vault` | `remember` / `recall` / `forget`，再注入最近几条 | 你不说「请记住」它会不会写；让它忘是不是真删 |
| C3 门控 | `dsh-memory-gate` | 先检索，再决定塞不塞；默认少塞 | 搜到了不一定塞进去；有没有为此再调一次模型 |
| C4 向量 + 图 | `dsh-memoria` | `observe` / `remember` / `search` / `recall`，带命名空间 | 两次信息能不能拼起来；会不会串工作区；自动抽取会不会写脏 |

装不上只记现象，不给这套题的质量分。

环境钉死，整周不要换：同一 DSH 版本、同一 profile（建议 `web`）、同一模型、同一套埋点句和追问。每个插件用干净工作区，别让上一个插件的 Markdown 或 SQLite 留着。

## 4. 每个插件怎么测（操作顺序）

每个插件都走同一套生命周期和评分步骤；埋点与追问提示按声明的协议生成。缺一步就不要给记忆分。

### 第一步：看它能不能跑（准入）

安装 → 启动 → 确认它活着。活着的样子可以是：有设置页、有记忆工具，或工作区里出现了 `MEMORY.md` 一类文件。

这一步过不了，后面的题不要做，也不要打「记性差」。

### 第二步：用大白话把事实说进去（会话 A，埋点）

`passive` 轨不要命令「请记住」，像平时聊天一样说事实。`guided` 轨保留同一句事实，但统一附加“请使用当前环境中已安装的持久记忆能力落实上面的信息、更新或遗忘请求”。提示只表达操作意图，不透露厂商工具名或标准答案。

埋点示例（整套题共用这批事实，不要即兴改字）：

- 「我叫林衡，工号是 DSH-1742，写代码偏好 Go。」
- 「这个项目叫北岸，包管理器用 pnpm。」
- 「我以前在杭州，已经搬到上海了。」

写没写进它的库，只看条数有没有增加、文件在不在。**不要把记忆原文导出到评测记录里。**

### 第三步：设屏障

关掉这轮对话。有余力就把 DSH 杀掉再开。新开一轮时，聊天记录里不该再出现上面那些原话。

### 第四步：用大白话追问（会话 B）

题目仍是普通人问法，例如：「我的工号和语言偏好是什么？」「北岸用什么装包？」「我现在在哪个城市，还在杭州吗？」`guided` 轨统一附加“回答前先使用当前环境中已安装的持久记忆检索能力；找不到就说不知道”。

### 第五步：对照标准答案打分

工号必须是 `DSH-1742`，城市必须是上海不是杭州。能对上号就对，对不上就错。能这样判的题，不必再找另一个模型当裁判。

一个插件整套跑完：卸掉插件，清掉它的库和文件，再测下一个。

## 5. 八 Tra 题（每题都要离开窗口才得分）

下面每题都是「会话 A 埋点 → 屏障 → 会话 B 追问」。T2 的两段信息不要塞在同一条可见窗口里再问。

| 题号 | 你在测什么 | 你怎么做 | 怎样算过 | 怎样算不过 |
| --- | --- | --- | --- | --- |
| T1 单跳 | 一句简单的话能不能记住 | 说过工号和偏好，新会话再问 | 工号 `DSH-1742` 和 Go 都说对 | 缺一个、说错、或编一个新工号 |
| T2 多跳 | 两次说的能不能拼起来 | 先说项目叫北岸；过一阵再说北岸用 pnpm；新会话问包管理器 | 答出 pnpm | 只记得项目名、或猜 npm / yarn |
| T3 更新 | 情况变了会不会改口 | 先说在杭州，后说已搬上海，再问现在在哪、还在杭州吗 | 答上海 | 还说杭州（记成旧的了） |
| T4 遗忘 | 让它忘，是不是真忘 | 写入工号后再明确让它删掉，再问工号 | 说不知道或已删除 | 仍说出 `DSH-1742` |
| T5 隔离 | 会不会串工作区 | 工作区甲里说口令 `red-α`，换到工作区乙再问这个口令 | 乙里不能漏出 `red-α` | 乙里复述出口令 |
| T6 拒答 | 没说过的会不会编 | 从没提过配偶 / 工资，却问「我配偶是谁」 | 明确说不知道 | 编一个名字或一段故事 |
| T7 预算 | 记了很多会不会把窗口塞爆 | 先灌 20 条无关事实，再埋 1 条有用的，只问那条 | 问的那条答对，且没有把 20 条全灌进窗口 | 答错，或明显整库灌窗 |
| T8 重启 | 关软件还在不在 | T1 写完后把 DSH 杀掉再开，再问 T1 | 还能答对 | 进程没了就不会了（只是缓存在进程里） |

T8 是「真持久」的底线。只过 T1、不过 T8，记录里要写清楚：跨会话可以，重启不行。

## 6. 分数怎么打

分两本账，**不要合成一个总分去排插件。** 答对是一回事，便宜、干净是另一回事。

### 6.1 对回答（主账，质量）

| 记什么 | 怎么记 | 人话 |
| --- | --- | --- |
| 记号准不准 | Exact / 关键词是否命中 | 工号、项目名、城市对上了没有 |
| 更新有没有改口 | T3 单独记 | 还说杭州 = 这题失败，即使其它都对 |
| 没说过的有没有瞎编 | T6 单独记 | 编造直接失败，不给「很会聊天」加分 |
| 让忘的还记不记得 | T4 单独记 | 仍说出工号 = 没忘掉 |

能精确匹配的题，不要上 LLM 裁判。只有改写太活、对不上记号时，才允许用裁判模型打「对 / 错」，并写明用了哪个裁判。

### 6.2 对过程（副账，成本与干净程度）

这些不和「答对」混成一个分，但要记下来，否则会出现「全对、但每次把整本记忆灌进去」的假第一。

| 记什么 | 怎么记 | 人话 |
| --- | --- | --- |
| 注入增量 | 记忆灌进窗口多了多少字 / token | 不是整段对话有多长，只算记忆插件新塞进去的那截 |
| 额外模型调用 | 抽取或重排有没有又打一次模型 | 多一次就更贵、更慢 |
| 写入 / 检索耗时 | 用会话事件上的时间戳相减 | 不要在旁边用秒表乱按，对不齐 |
| 搜到几条 vs 真正塞进去几条 | 能观察到就记 | 有的插件故意少塞，这是优点，不是漏记 |

插件如果只写自己的 SQLite、不往会话事件里打点：评测后只对比条数增减，**不导出记忆原文。**

### 6.3 怎么读结果

- C0 跨会话几乎全错，其它条件有对有错：题有效，可以比插件。
- 某插件 T1、T2 过、T3 不过：会记，不会改口。
- 某插件答题全对、T7 整库灌窗：质量过关，生产上可能很贵。
- 某插件装不上：只有安装记录，没有记忆质量结论。

## 7. 协议诊断与跨轨解释

`passive` 与 `guided` 都是正式结果，但回答不同问题：前者衡量零提示便利性，后者衡量插件在其预期交互方式下的能力。工具型插件在 `passive` 失败、`guided` 成功，结论应写成“记忆能力可用，但需要显式触发”，不能写成“记忆差”，也不能把 `guided` 分数塞回 `passive` 榜。

| 跨轨结果 | 结论怎么写 |
| --- | --- |
| 强迫写入后能跨会话召回 | 它有记忆，只是不会自己从聊天里抽取 |
| 强迫写入仍召不回 | 存或取坏了 |
| 库里条数增加了，嘴上却答不出来 | 存进去了，但没塞回给模型，或模型没用 |
| 默认需要人工同意，非交互配置后能写入 | 同时报告默认审批策略和评测覆盖配置，不伪装成开箱即用 |

同一插件可同时跑两轨做机制诊断，但每轨必须带自己的同协议 C0，runId 和排行榜必须保留协议名。

## 8. 最容易骗自己的三件事

1. **同一窗口里追问。** 测到的是上下文，不是记忆。
2. **上一个插件的文件或数据库没清干净。** 下一个会莫名其妙全对。
3. **拿别人论文里的记忆分数来比 DSH 插件。** 那个分在这里没有意义。

另外不要做：两个记忆插件叠装；把压缩 / 截断的表现写进本组；装失败却打「记忆差」。

## 9. 记录模板

每个插件、每道题复制一份。测完把事实填进去，不要事后凭印象改。

```text
插件：
版本 / 提交：
DSH 版本 / Profile / 模型：
条件：C0 / C1 / C2 / C3 / C4
题号：T1 … T8
安装：成功 / 失败
启动：成功 / 失败
屏障：仅关会话 / 关会话且重启 DSH
任务结果：成功 / 失败 / 部分
回答要点（不要贴记忆库原文）：
过程：注入增量 / 额外模型调用 / 耗时 / 搜到条数 vs 注入条数
二次诊断（如有）：未做 / 强迫写入后能召回 / 仍不能 / 要审批
限制与风险：
置信度：高 / 中 / 低 / 暂不推荐
测试人 / 日期：
```

一组插件全部测完后，先看 C0 是否「该错的都错了」，再并排看 T1–T8，最后才看过程账。不要先排一个总分。
