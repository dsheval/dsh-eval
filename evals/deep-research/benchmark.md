# DSH Deep Research 插件测评基准 V2

研究不等于搜索。搜到链接只说明检索发生了；形成有交付物、可核验引用和明确边界的报告，才算完成研究。

## 1. 测试对象与对照

- C0：DSH 默认能力，不安装额外 Deep Research 插件。
- P1–P8 保留在候选名录；本轮实际测试 P1–P6、P8，每次只安装一个待测插件。
- P7 因本轮不提供 `AI4SCHOLAR_API_KEY` 被明确排除：不运行、不计零分、不进入榜单。
- 不设置 C1；搜索能力是过程诊断项，不拆成第二个实验组。
- 同一轮锁定 DSH 版本、模型、系统配置、题面、网络、超时和 Judge 配置。
- 每个条件使用独立 `DSH_HOME` 和工作区，禁止复用上一插件的会话、缓存或报告。

安装失败、缺 Key、操作系统不兼容或人工 Gate 未配置时，记录准入结论，不给质量零分。

## 2. 题集

V2 有 8 个独立题面和 10 个测评项，固定组成是 2 + 2 + 4 + 2：

- R1–R2：xbench-DeepSearch `2505` 两道中文短事实题，覆盖官方数据聚合与技术计算。
- R3–R4：BrowseComp-ZH 两道中文多跳短事实题，覆盖历史文化地点和学术论文反向识别。
- R5–R8：DeepResearchEval `v1` 四道公开英文长文题，覆盖科技、健康、金融和交通。
- R9：复用 R5，执行中断后恢复。
- R10：复用 R5 产物，区分“搜到结果”和“完成研究”。

R1–R4 的 prompt、gold、上游 task ID 和来源哈希保存在 Git 忽略的本机私有文件，禁止提交明文。R5–R8 的公开原题、上游 task ID 和来源哈希在 `fixtures/suite.json` 中冻结。R9/R10 是本地产品诊断，不计入上游官方指标。

该 10 项集用于 DSH 插件小样本横评，不是 BrowseComp-ZH、xbench 或 DeepResearchEval 的官方完整榜单；尤其不能对外宣称为正式中文 Deep Research 榜单。

## 3. 两本账

### 过程账

每题只保留八类数据：

1. 环境：DSH、模型、插件版本与配置指纹。
2. 研究步骤：计划、子问题及完成情况。
3. 工具行为：搜索、抓取、解析、写作调用。
4. 来源：总数、可打开链接、独立域名、一手来源。
5. 异常：错误、超时、重试、降级、人工介入。
6. 恢复：中断点、是否续做、是否重复从头开始。
7. 资源：时间、输入/输出 Token、费用。
8. 产物：报告、表格、文件及版本是否存在。

过程数据用于解释成败和比较效率，不能以“搜得多、调用多、写得长”直接换取质量分。

### 结果账

每题只保留八类数据：

1. 状态：`PASS / PARTIAL / FAIL / SYSTEM_ERROR / OUT_OF_SCOPE / GRADER_ERROR`。
2. 事实：正确、错误、缺失。
3. 交付物：必需项数量、完成数量、完整率。
4. 引用：总数、可打开数、忠实度、关键结论覆盖率。
5. 研究完成度：`COMPLETE / SEARCH_ONLY / INCOMPLETE`。
6. 风险：编造事实、编造引用、冲突处理。
7. 恢复：`PASS / FAIL / NOT_TESTED`。
8. 相对 C0：`POSITIVE / NO_CLEAR / NEGATIVE / NOT_COMPARABLE`。

## 4. 确定性检查与 LLM Judge

R1–R4 使用本机私有 gold 的精确或可接受答案匹配，并要求实际发生多步检索或抓取。上游主指标是 `official.answer_accuracy`；引用正确性、完整性、来源质量和时效性只作诊断列，不改写答案准确率。

长文先做确定性检查：

- 强制交付物是否存在。
- URL 数量是否达到题面要求。
- URL 是否可打开。
- 禁止项是否出现。
- 是否只有链接列表而没有综合报告。

随后由 LLM Judge 评价事实正确性、交付物完整性、引用忠实度、研究完成度和风险。Judge 必须：

- 正式长文评测默认启用，从本地 DSH 凭证或环境变量读取 DeepSeek Key；只有显式诊断模式可关闭。
- 使用固定模型和固定提示词。
- 不知道插件身份，避免品牌偏差。
- 只输出结构化 JSON。
- 记录 Judge 模型、请求状态和 Token，不记录 Key。
- API 余额不足、限流、超时或解析失败时标 `GRADER_ERROR`，不得记质量零分。

链接可打开不等于引用忠实。最终引用忠实度必须由 Judge 或人工抽检确认来源是否真的支持相邻结论。

DeepResearchEval 的 `official.quality_score` 与 `official.fact_ratio` 必须分栏保留，不能加权融合。本套代码默认使用固定 DeepSeek Judge 做本地插件横评代理；除非显式调用并记录上游官方适配器，否则不得把本地 Judge 分数标成上游官方分数。

## 5. 单题判定

- `PASS`：关键交付物齐全，无严重编造，引用和事实达到题面门槛。
- `PARTIAL`：产物可用，但有非致命缺项或证据覆盖不足。
- `FAIL`：关键交付物缺失、关键事实错误、伪造来源，或只交搜索列表。
- `SYSTEM_ERROR`：模型、插件、网络或 Host 未产生可评分产物。
- `OUT_OF_SCOPE`：领域插件明确说明题目超出能力边界，且没有硬编报告。
- `GRADER_ERROR`：有产物，但 Judge 无法完成；保留确定性检查，暂不进入 Judge 质量排名。

## 6. 运行顺序

1. 只读预检题集、插件、凭证引用和平台兼容性。
2. 先跑 C0，检查短事实题是否闭卷泄漏及长文是否存在天花板/地板效应。
3. 冻结题面后，P1–P6、P8 每次只运行一个插件；P7 保持排除。
4. R1–R8 正常执行；R9 做中断恢复；R10从 R5 记录派生，不再次调用模型。
5. 选 R2、R6、R8 做稳定性复跑；首轮只对 C0 和晋级插件复跑。
6. 生成逐题记录、插件汇总和多指标榜单。

## 7. 榜单规则

不把所有维度加权成一个模糊总分。采用门槛加字典序：

1. 先排除未准入、严重伪造或有效样本不足者。
2. 先比较长文 PASS 数与引用忠实度。
3. 再比较短事实 PASS 数、恢复能力和负增量题数。
4. 质量相近时，才用系统失败率、时间、Token 和成本破同分。

最终必须同时展示正增量、无明显增量、负增量和系统失败，不能只展示名次。
